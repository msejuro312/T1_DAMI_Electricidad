1. ¿Qué hace la aplicación?

Es una app Android que estima el consumo mensual de energía eléctrica y su costo de un equipo. El usuario ingresa cuatro datos en un formulario:

  1. Nombre del usuario (texto).
  2. Potencia del equipo en vatios (W), entre 0 (excluido) y 10000.
  3. Horas de uso diario (h/día), entre 0 (excluido) y 24.
  4. Tarifa por kWh en soles (S/), entre 0 (excluido) y 10.

Al pulsar Calcular, la app aplica estas dos fórmulas considerando un mes de 30 días:

Consumo mensual (kWh) = (potencia / 1000) x horas x 30
Costo mensual (S/)    = consumo mensual x tarifa

Después clasifica el consumo en tres niveles y envía los resultados a una segunda pantalla (pantalla de resultado), donde se muestran los valores con dos decimales y la clasificación. Un botón Volver regresa al formulario sin perder lo que el usuario escribió.

ClasificaciónRegla (consumo sin redondear)
Consumo bajoconsumo ≤ 100 kWh
Consumo moderado100 kWh < consumo ≤ 200 kWh
Consumo altoconsumo > 200 kWh

2. Arquitectura del proyecto: sus partes

El proyecto es una app Android estándar escrita en Kotlin con interfaz en XML (no usa Compose). Su arquitectura es simple: dos pantallas (Activities) que se comunican pasando datos por un Intent, más los recursos visuales y de texto en XML.

activity_main.xmlFormulario (vista) → MainActivity.ktValida, calcula, clasifica → Intent + extrasnombre, primario,
secundario, clasificacion → ResultadoActivity.ktRecibe y muestra → activity_resultado.xmlResultado (vista) buttonVolver → finish()Regresa al formulario con los datos intactos

Idea central de la arquitectura: cada Activity tiene su vista XML y su archivo Kotlin. La lógica (validación y cálculo) vive únicamente en MainActivity; ResultadoActivity solo recibe y muestra. No hay clases de modelo ni bases de datos: los datos viajan de una pantalla a otra dentro del Intent.

3. Flujo de ejecución paso a paso

  1. Arranque: Android lanza MainActivity. En onCreate() se infla activity_main.xml con ViewBinding y se muestra el formulario.
  2. Registro de eventos: se asocia el botón Calcular a la función calcularYMostrarResultado() y se configuran los cuatro doAfterTextChanged para borrar el error de cada campo cuando el usuario escribe de nuevo.
  3. Lectura: al pulsar el botón se leen los 4 valores. El nombre se convierte a texto limpio (trim()); los tres números pasan por funciones leerX() que devuelven Double o null si el dato no es válido.
  4. Validación (E04): si el nombre está vacío o algún número es null, se muestra el mensaje de error en el TextInputLayout correspondiente y la función hace return: no se navega.
  5. Cálculo (E05): con datos válidos se calcula el consumo y el costo con Double (sin redondear).
  6. Verificación de finitud: si el resultado no fuera un número finito, se muestra error_calculo y no se navega.
  7. Clasificación (E05): un when decide entre "Consumo bajo", "Consumo moderado" o "Consumo alto".
  8. Navegación (E06): se crea un Intent hacia ResultadoActivity y se cargan 4 extras: "nombre" (String), "primario" (Double: consumo), "secundario" (Double: costo) y "clasificacion" (String). Luego startActivity(intent).
  9. Presentación: ResultadoActivity.onCreate() infla su layout, llama a mostrarResultado() que lee los extras con getStringExtra/getDoubleExtra y los escribe en los cuatro TextView usando strings con formato (%1$.2f = dos decimales).
  10. Regreso: buttonVolver ejecuta finish(), destruye la pantalla de resultado y deja MainActivity viva con todo el formulario tal como estaba.

4. Conceptos clave explicados

ViewBinding (E01)

Mecanismo que genera automáticamente una clase (ActivityMainBinding) a partir del archivo XML. Permite acceder a los controles por su id sin usar findViewById(). Requiere dos pasos: habilitarlo en Gradle con buildFeatures { viewBinding = true } y luego, en cada Activity, inflar el layout:

binding = ActivityMainBinding.inflate(layoutInflater)
setContentView(binding.root)

Después, cada control se usa como binding.editTextNombre, binding.buttonCalcular, etc. Compilador detecta errores de id en tiempo de compilación.

Activity

Una pantalla con su propio ciclo de vida. onCreate() es el método que se ejecuta al crearla: ahí se configura la vista y los eventos. finish() la cierra y regresa a la anterior.

Intent y extras (E06)

Un Intent es el mensaje que pide a Android abrir otra Activity. Los extras son los datos que viajan dentro de ese mensaje, como un sobre con pares clave/valor:

putExtra("primario", consumo)              // envía un Double
val c = intent.getDoubleExtra("primario", 0.0)  // recibe el Double

Reglas importantes del examen: las claves deben coincidir exactamente (un error de tipeo como "secunadario" haría que el dato no llegue), los números se envían como Double (nunca convertidos a String) y no se usan Serializable/Parcelable ni clases de modelo.

Validación con funciones que devuelven nullable

Cada campo numérico tiene una función leerX(valor: String): Double?. El signo ? significa que puede devolver un número o null (dato inválido). La función aplica cuatro filtros en orden:

  1. trim(): quita espacios al inicio y final.
  2. replace(',','.'): acepta coma decimal (opcional) normalizándola a punto.
  3. toDoubleOrNull(): si el texto no es número (vacío, letras) devuelve null.
  4. isFinite(): descarta NaN e Infinity; luego verifica el rango permitido.

Así, con una sola línea se rechazan vacíos, texto, ceros, negativos y valores fuera de límite.

Limpiar errores con doAfterTextChanged

Se registra un escuchador por campo: en cuanto el usuario escribe, el error se pone en null y desaparece de la pantalla. Así el formulario no queda "enrojecido" si el usuario corrige el dato.

when (clasificación)

Es el equivalente a switch de Kotlin, pero permite comparar condiciones. Se evalúa de arriba hacia abajo y se detiene en la primera condición verdadera:

return when {
    consumo <= CONSUMO_BAJO     -> getString(R.string.clasificacion_1) // ≤ 100
    consumo <= CONSUMO_MODERADO -> getString(R.string.clasificacion_2) // ≤ 200
    else                        -> getString(R.string.clasificacion_3) // resto
}

Los valores límite están en companion object como constantes: se escriben una vez (100.0, 200.0) y se reutilizan; además evitan "números mágicos" en el código.

Recursos de texto con formato

Nunca se escriben los textos "a mano" dentro del Kotlin: se definen en strings.xml y se cargan con getString(). Para incluir números se usan marcadores:

<string name="resultado_primario_formato">Consumo mensual: %1$.2f kWh</string>

%1$.2f significa: primer argumento, formato decimal con 2 cifras después del punto. Al llamar getString(R.string.resultado_primario_formato, primario) el 150 se convierte en 150.00. La ventaja: si mañana cambia el texto, no se toca el Kotlin.

Explicación

  • minSdk = 26: versión Android mínima soportada. compileSdk / targetSdk = 36: versión con la que se compila y apunta.
  • JavaVersion.VERSION_17: nivel de Java/Kotlin usado por el compilador.
  • dependencies: librerías base (AppCompat, Material para los TextInputLayout y botones, ConstraintLayout). No se tocaron.

5.3 AndroidManifest.xml — E06 Registrar ResultadoActivity

Qué se hizo: se agregó el bloque de la segunda actividad con android:exported="false".

<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:roundIcon="@mipmap/ic_launcher_round"
        android:supportsRtl="true"
        android:theme="@style/Theme.ExamenBeca">
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />

                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>
        <activity
            android:name=".ResultadoActivity"
            android:exported="false">

        </activity>
    </application>

</manifest>

Explicación

  • android:name=".ResultadoActivity": registra la clase ante el sistema. Si falta esta línea, al hacer Intent(this, ResultadoActivity::class.java) la app crashea con ActivityNotFoundException. El punto inicial significa "paquete raíz del proyecto".
  • exported="false": solo esta app puede abrir esa pantalla (es un requisito del enunciado; como no tiene intent-filter, es lo correcto).
  • MainActivity tiene exported="true" y un intent-filter con MAIN/LAUNCHER: por eso es la pantalla de inicio visible en el ícono del celular.
  • android:label: nombre de la app mostrado por Android (viene de app_name en strings.xml).

5.6 MainActivity.kt — E04 E05 E06

Qué se hizo: ViewBinding completo, los cuatro limpiadores de error, la validación del formulario, las lecturas seguras de los 3 números, ambos cálculos, la clasificación con when, la verificación de finitud y el envío de los 4 extras.

package com.cibertec.electricidad

import android.content.Intent
import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity
import androidx.core.widget.doAfterTextChanged
//E01
import com.cibertec.electricidad.databinding.ActivityMainBinding

// E01: agregar el import de ViewBinding después de habilitarlo en Gradle.
class MainActivity : AppCompatActivity() {
    // E01: declarar la propiedad binding para activity_main.xml.

    private lateinit var binding: ActivityMainBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // E01: reemplazar la carga provisional por la inflación con ViewBinding.
        binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        binding.buttonCalcular.setOnClickListener {
            calcularYMostrarResultado()
        }

        binding.editTextNombre.doAfterTextChanged {
            binding.inputLayoutNombre.error = null
        }

        binding.editTextPotencia.doAfterTextChanged {
            binding.inputLayoutPotencia.error = null
        }

        binding.editTextHoras.doAfterTextChanged {
            binding.inputLayoutHoras.error = null
        }

        binding.editTextTarifa.doAfterTextChanged {
            binding.inputLayoutTarifa.error = null
        }

    }



    private fun calcularYMostrarResultado(){

    // E05: implementar ambos cálculos y la clasificación con when en esta Activity.
        // Puede organizar la lógica en funciones privadas de esta misma Activity.
        // E06: enviar directamente con Intent.putExtra: "nombre" y "clasificacion"

        val nombre = binding.editTextNombre.text.toString().trim()
        val potencia = leerPotencia(binding.editTextPotencia.text.toString())
        val horas = leerHoras(binding.editTextHoras.text.toString())
        val tarifa = leerTarifa(binding.editTextTarifa.text.toString())
        var formularioValido = true

        if (nombre.isBlank()){
            binding.inputLayoutNombre.error = getString(R.string.error_nombre)
            formularioValido = false

        }

        if (potencia == null){
            binding.inputLayoutPotencia.error = getString(R.string.error_potencia)
            formularioValido = false

        }

        if(horas == null){
            binding.inputLayoutHoras.error = getString(R.string.error_horas)
            formularioValido = false
        }

        if(tarifa == null){
            binding.inputLayoutTarifa.error = getString(R.string.error_tarifa)
            formularioValido = false
        }

        if(!formularioValido || potencia == null || horas == null || tarifa == null) {
            return
        }

        val consumo = calcularConsumo(potencia,horas)

        val costo = calcularCostoMensual(consumo,tarifa)

        if(!consumo.isFinite() || !costo.isFinite()) {
            binding.inputLayoutTarifa.error = getString(R.string.error_calculo)
            return
        }

        val clasificacion = clasificarConsumo (consumo)


        val intent = Intent(this, ResultadoActivity::class.java).apply {
            putExtra("nombre",nombre)
            putExtra("primario", consumo)
            putExtra("secundario", costo)
            putExtra("clasificacion",clasificacion)
        }
        startActivity(intent)


    }

    private fun leerPotencia (valor: String): Double? {
        val normalizado = valor.trim().replace(',','.')
        val potencia = normalizado.toDoubleOrNull() ?: return null
        if(!potencia.isFinite()) return null
        return if (potencia > POTENCIA_MINIMA && potencia <= POTENCIA_MAXIMA) potencia else null
    }

    private fun leerHoras (valor: String): Double? {
        val normalizado = valor.trim().replace(',','.')
        val horas = normalizado.toDoubleOrNull() ?: return null
        if(!horas.isFinite()) return null
        return if (horas > HORAS_MINIMA && horas <= HORAS_MAXIMA) horas else null
    }

    private fun leerTarifa (valor: String): Double? {
        val normalizado = valor.trim().replace(',','.')
        val tarifa = normalizado.toDoubleOrNull() ?: return null
        if(!tarifa.isFinite()) return null
        return if (tarifa > TARIFA_MINIMA && tarifa <= TARIFA_MAXIMA) tarifa else null
    }

    private fun calcularConsumo(potencia: Double, horas: Double): Double{
        return (potencia/1000) *horas * 30

    }

    private fun calcularCostoMensual(consumo: Double, tarifa: Double): Double{
        return consumo*tarifa

    }

    private fun clasificarConsumo(consumo: Double): String{
        return when {
            consumo <= CONSUMO_BAJO -> getString(R.string.clasificacion_1)
            consumo <= CONSUMO_MODERADO -> getString(R.string.clasificacion_2)
            else -> getString(R.string.clasificacion_3)

        }
    }

    companion object {
        const val POTENCIA_MAXIMA = 10000.0
        const val POTENCIA_MINIMA = 0.0
        const val HORAS_MAXIMA = 24.0
        const val HORAS_MINIMA = 0.0
        const val TARIFA_MAXIMA = 10.0
        const val TARIFA_MINIMA = 0.0
        const val CONSUMO_BAJO = 100.0

        const val CONSUMO_MODERADO = 200.0



    }


}

Explicación parte por parte

a) Imports y ViewBinding (E01). import android.content.Intent sirve para navegar; doAfterTextChanged da el evento "se modificó el texto"; ActivityMainBinding es la clase generada a partir de activity_main.xml. La propiedad private lateinit var binding guarda ese objeto: lateinit indica que se inicializa después (en onCreate), no en el momento de declararla.

b) onCreate(). Es el punto de entrada. Hace tres cosas: (1) infla el XML y lo muestra con setContentView(binding.root); (2) conecta el botón Calcular a la función que hace todo el trabajo —setOnClickListener solo registra qué se ejecuta al pulsar—; (3) registra cuatro doAfterTextChanged que borran el error de cada campo en cuanto el usuario escribe de nuevo (cumple "limpiar errores al volver a calcular").

c) calcularYMostrarResultado() — el corazón del examen. Se ejecuta solo al pulsar el botón. Secuencia:

  1. Lectura: el nombre se obtiene con .text.toString().trim() (quita espacios). Los tres números pasan por leerPotencia/leerHoras/leerTarifa, que devuelven Double válido o null.
  2. Bandera formularioValido: comienza en true. Cada validación fallida la pone en false y coloca el mensaje en el campo indicado:
    • Nombre: isBlank() detecta vacío o solo espacios → error en inputLayoutNombre.
    • Potencia / horas / tarifa: basta con que sean null (la función leerX ya cubre vacío, texto, fuera de rango y no finito) → error en su respectivo inputLayout.
    Se evalúan los cuatro campos siempre (no se corta con else if), por eso el usuario ve todos los errores de una sola vez.
  3. Bloqueo de navegación: if (!formularioValido || ...) return detiene la función antes de calcular o abrir la otra pantalla. Este es el punto clave de la validación.
  4. Cálculo: calcularConsumo() y calcularCostoMensual() devuelven Double sin redondear.
  5. Finitud: si alguno no fuera finito (caso teórico de desbordamiento) se muestra error_calculo y se retorna sin navegar.
  6. Clasificación: clasificarConsumo() devuelve uno de los tres textos.
  7. Envío (E06): se construye el Intent con .apply { } para cargar los extras y se llama startActivity(intent).

d) Las funciones leerX(valor: String): Double?. Las tres son idénticas salvo el rango. Paso a paso: normalizan el texto (trim + coma a punto), intentan convertir con toDoubleOrNull() (si falla → null), descartan números no finitos con isFinite() y finalmente exigen el rango. El operador ?: return null significa: "si la conversión falló, devuelve null y no sigas". Así una sola función rechaza vacío, texto, 0, negativos y valores fuera de límite.

e) Los cálculos (E05). calcularConsumo aplica (potencia/1000) * horas * 30: la potencia en W se pasa a kW, se multiplica por las horas diarias y por los 30 días del mes. calcularCostoMensual multiplica ese consumo por la tarifa. Ambas declaran : Double como tipo de retorno.

f) La clasificación con when (E05). Se compara con <= (menor o igual), no con <, porque la tabla del enunciado dice que 100 kWh exactos es "bajo" y 200 exactos es "moderado". El else cubre todo lo que queda (mayor a 200 = "alto"). Los límites están como constantes en el companion object.

g) companion object. Es un contenedor de constantes y miembros estáticos de la clase (solo existe una copia, no depende de una instancia). Aquí vive el catálogo de límites: POTENCIA_MAXIMA = 10000.0, HORAS_MAXIMA = 24.0, TARIFA_MAXIMA = 10.0, CONSUMO_BAJO = 100.0 y CONSUMO_MODERADO = 200.0. Especialmente en validaciones, tenerlas centralizadas evita errores y facilita cambiar reglas en un solo lugar.

h) El Intent y sus claves (E06). Se enviaron exactamente cuatro extras:

Clave (String literal)ValorTipo
"nombre"Nombre del usuarioString
"primario"Consumo mensual (kWh)Double
"secundario"Costo mensual (S/)Double
"clasificacion"Texto de la clasificaciónString

Las claves deben escribirse idénticas en el envío y en la recepción; un solo carácter distinto hace que el extra no llegue y el dato quede en su valor por defecto. Los números viajan como Double, sin convertir a String (requisito explícito del enunciado).

5.7 ResultadoActivity.kt — E06 Recepción y presentación

Qué se hizo: completar ViewBinding, recibir los extras, mostrar los cuatro datos y conectar el botón Volver.

package com.cibertec.electricidad

import android.os.Bundle
import androidx.appcompat.app.AppCompatActivity

//E01
import com.cibertec.electricidad.databinding.ActivityResultadoBinding

// E01: agregar el import de ViewBinding después de habilitarlo en Gradle.
class ResultadoActivity : AppCompatActivity() {
    // E01: declarar la propiedad binding para activity_resultado.xml.

    private lateinit var binding: ActivityResultadoBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // E01: reemplazar la carga provisional por la inflación con ViewBinding.
        binding = ActivityResultadoBinding.inflate(layoutInflater)
        setContentView(binding.root)

        mostrarResultado()

        binding.buttonVolver.setOnClickListener {
            finish()
        }
    }

    private fun mostrarResultado(){
        val nombre = intent.getStringExtra("nombre") ?: getString(R.string.valor_no_disponible)
        val primario = intent.getDoubleExtra("primario",0.0)
        val secundario = intent.getDoubleExtra("secundario", 0.0)
        val clasificacion = intent.getStringExtra("clasificacion")?: getString(R.string.valor_no_disponible)

        binding.textViewNombreResultado.text = getString(R.string.resultado_nombre_formato,nombre)
        binding.textViewPrimario.text = getString(R.string.resultado_primario_formato, primario)
        binding.textViewSecundario.text = getString(R.string.resultado_secundario_formato, secundario)
        binding.textViewClasificacionResultado.text = clasificacion
    }

}

Explicación

  • Mismo patrón de ViewBinding que MainActivity, pero con ActivityResultadoBinding (generado de activity_resultado.xml).
  • onCreate hace tres cosas en orden: inflar, mostrar los datos (mostrarResultado()) y escuchar el botón Volver.
  • Recepción de extras:
    • intent.getStringExtra("nombre") devuelve el String; el operador ?: (elvis) indica: "si por alguna razón no llega, usa el texto valor_no_disponible" para que la pantalla nunca muestre vacío.
    • intent.getDoubleExtra("primario", 0.0) devuelve el Double con su valor por defecto 0.0. Las claves son las mismas que usó MainActivity.
  • Presentación: cada TextView se actualiza con .text = ...:
    • resultado_nombre_formato → "Resultado de Alvaro" (%1$s inserta el texto recibido).
    • resultado_primario_formato → "Consumo mensual: 150.00 kWh" (%1$.2f formatea el Double con 2 decimales).
    • resultado_secundario_formato → "Costo mensual: S/ 120.00".
    • textViewClasificacionResultado recibe directamente el texto de clasificación (ya viene listo desde MainActivity).
  • buttonVolver → finish(): cierra ResultadoActivity y regresa a MainActivity, que sigue en memoria: el formulario conserva todos los valores escritos. Por eso no se usa startActivity para volver.
  • Esta Activity no calcula nada: toda la lógica vive en MainActivity, tal como pide el enunciado.

7. Errores típicos que se corrigieron

Estos son los fallos que aparecieron durante el desarrollo y sirven como aprendizaje para futuras evaluaciones:

ErrorConsecuenciaCorrección
Usar // como comentario en strings.xml XML inválido: falla la compilación de recursos (AAPT). Comentario XML: <!-- ... --> o eliminarlo.
Funciones con return pero sin declarar : Double Error de compilación: Kotlin espera Unit y recibe Double. Declarar el tipo de retorno: fun calcularConsumo(...): Double.
Usar constantes no declaradas (CONSUMO_BAJO sin definir) Error de compilación: referencia no resuelta. Agregarlas al companion object.
Mostrar el error de nombre en inputLayoutPotencia El error aparecía en el campo equivocado. Asignarlo a inputLayoutNombre.
Comparar con < en la clasificación 100 kWh daba "moderado" en vez de "bajo". Usar <= en los dos límites.
Tipo de clave mal escrito: "secunario" / "secunadario" El extra no llegaba: el costo se mostraba 0.00. Las claves deben ser idénticas: "secundario".
Llamar getStringExtra(R.string.algo) Error de compilación: ese método recibe un String, no un Int de recurso. Usar getStringExtra("clave") con la clave enviada por la otra Activity.
Olvidar registrar la Activity en el Manifest ActivityNotFoundException y cierre abrupto de la app. Declararla con android:exported="false".
